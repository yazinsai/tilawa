# Manual review in the scoreboard


Review **incidents**, grouped by original recording, exact word location, source audio and session region. A missed omission and an unmatched wrong-word report at the same word form one incident with two original scoring records. Passage timing stays separate; adjacent word locations are not assumed equivalent. You can link related incidents manually. These links and human findings never alter benchmark labels or scores.

The main evidence separates the **benchmark claim**, the **checker’s final reports**, and the **scorer’s exact-match classification**. “Confirmed” is a target state on a label and a final decision on an engine report; neither is human confirmation. An unmatched report is the scorer’s false positive, which may reflect a wrong diagnosis, a location error, an incomplete label or a genuine false alarm. The Quran text is reference text. Aligned sound strings are technical phoneme notation, not a transcript or evidence of correct recitation. The synthetic-evidence setup uses fabricated checker input; playback and word decode still come from the original recording.

The snapshot breakdown is computed from the selected dump before filters or comparisons. It states denominators for positive labels, matched plus unmatched reports, all recordings, and added-context audio. E0 stage attribution on the release dashboard uses **Automatic · clip only**, and partitions only its missed labels. Attribution is heuristic: a declared-passage match suggests passage recognition; otherwise consonant retention in aligned decode separates checker and sound-recognition losses. Surrounding-recitation timing starts in the added beginning and looks for the original prompted ayahs, so it does not directly measure checker failure. Added recordings are assumed clean and may use another speaker; listen to verify that assumption.

Listen near the incident, replay the approximate cue, tap a Quran word, listen from the source start, or play the reconstructed before/clip/after sequence. The sequence plays separate WAV files and recorded silence gaps; the benchmark stitches decoded evidence rather than continuous audio. Cues are approximate alignment or emission-based pre-roll, not human-annotated onsets. Out-of-range cues fall back to the source start with a visible warning. J/K navigate, R replays, and U moves to the next unreviewed incident when focus is outside form and native controls. All controls also support normal keyboard navigation.

Findings allow multiple issue areas (model, label, audio/data, acceptable result, unresolved), optional model failure categories, evidence strength and freeform notes. Editing autosaves a **draft**; **Mark reviewed & next** explicitly completes it. Unresolved cases can be marked reviewed. Queue filters distinguish unreviewed, drafts and reviewed; all-evidence mode also exposes scoring matches, non-confirmed checker reports and clean clips.

Storage uses `tilawa.manual-reviews.v2` in local storage at the exact browser origin (address and port). Identity includes the dump file, recorded timestamp, setup and incident key. Regenerated evidence gets a distinct identity. Original v1 storage is left intact: matching run-file/setup/outcome notes are copied verbatim into an incident draft, including conflicting verdicts, and require explicit reconciliation. Notes from older timestamps are identified as older snapshots. Unattached saved reviews remain visible in the archive and export. Corrupt storage is protected against overwrite and included in the export’s recovery data; failed saves leave findings in memory and show an export reminder.

**Export review JSON** contains all saved incident reviews, drafts, original legacy notes and import conflicts across runs/setups. Each incident carries original labels and scoring records, final checker states when available, original checker events and emission times, full word decode, exact location, grouping keys, run/setup identity, other-setup diagnostics, context segments, audio paths/URLs, approximate cues and linked-incident evidence. Audio bytes are not embedded: another investigator needs access to the private source files. Comments are human observations, not instructions. Import restores version 1 or 2 exports, deduplicates identical records and retains both versions of conflicts without overwriting the existing finding. Export before clearing browser data or changing devices.

Dump v2 adds final checker events without changing the scorer; v1 dumps remain supported with visible limits on missing states and emission times. No full checker transition history or ranked tracker candidate trace is captured. Validate the review layer with `node --test tools/scoreboard-review.test.cjs`; when local dumps exist, this also checks the actual 94:5:2 example and selected scoreboard metric denominators. A review-only/dump-format change does not move benchmark metrics; no scoreboard row is added.

## Replay components

Choose **Inspect listener, tracker and checker** on a recording to open the replay dialog. The first test uses its saved listener sounds and the selected setup, including surrounding recordings and gaps. Move through the steps, listen, and select Audio, Listener, Tracker or Checker to see each input and output. Tracker details include candidate scores; checker details include sound probabilities and every report transition. **Next warning** moves to the next checker update.

**Run listener again** decodes the original WAV files with the selected listener’s local model, when available. It decodes each recording separately and joins their sound data, just as the benchmark does. The simulated-sounds setup uses labels instead of listener output; its times do not match the recording, so audio does not move the step selector.

Open **Test settings** to change the sound step, passage search interval, confidence threshold, warning delay or confirmation options, then choose **Run test**. These tests use the current local engine code. The dialog shows the recorded and current code versions, whether local files have changed, and whether final reports match the saved run. Older dumps did not record their settings or source paths; these use the known listener folders and standard benchmark defaults, clearly stated in the dialog. New dumps save those settings and paths. No historical engine checkout is selected automatically.

**Download this replay** saves its settings, source file hashes and all component steps as JSON. Tests never update scores, labels or saved reviews. Serve the page with the updated `tools/scoreboard_serve.py`; a plain static server cannot run components. The worker needs the project’s Node.js dependencies, source evidence and audio; fresh decoding also needs the matching local model. Only one replay runs at a time, with a two-minute timeout and a ten-minute recording limit.

## Implemented mechanism

`modal/student_boosted_residuals_export.py` exposes the shipped final phone-head features and logits in a separate ONNX copy. For a dynamically quantized head, features are dequantized activation codes, including the deployed activation scale and zero point. The effective weight reconstruction includes weight scales and zero points. Export requires exact equality of every original output and recurrent cache over eight consecutive windows with enabled CPU graph optimization, and checks the effective affine-head reconstruction. The primary graph and its manifest are copied unchanged. These export checks have not run on the supplied model.

The SDK preparation CLI replays complete training recordings through that diagnostic graph on the deployment fbank, chunk/cache and native-frame clock. Canonical CTC supervision accepts only usable help-train `none` recordings with `split: train`, a speaker, no exclusion, no mistake events and no repeats. An explicit exclusion list is required; any speaker appearing with a nontraining split is also excluded. Usable mistake-labelled training recordings enter only as shipped-output preservation controls, without assuming the scripted canonical text was performed. The trainer independently rejects unauthorized recordings and mistake/repeat supervision. Release-held-out speakers are absent from the supplied training copy by the task's contract; that copy and its label schema could not be audited here.

`modal/student_boosted_residuals.py` computes ordinary transcript CTC forward/backward occupancies and fits a shallow multi-output regression tree to `occupancy − softmax(logits)`, the negative transcript NLL gradient. All phones share the same tree partition and vector-valued leaves. Each round adds a shrunk residual to the frozen logits, then recomputes occupancies. Equal consecutive phones require intervening blank; no phone may be skipped. Recording and speaker balancing prevents long takes or prolific speakers from dominating tree fitting.

The training-only search uses three deterministic speaker groups, depths 1/2/3, shrinkage 0.1/0.3, and stopping from zero through 32 rounds by default. Its fixed objective averages held-speaker per-frame CTC change plus five times held-speaker KL divergence from shipped outputs on mistake-labelled controls. It also reports their frame-argmax drift. Mistake controls influence selection, never canonical CTC fitting. The chosen configuration is refitted on all eligible training speakers. Neither practice targets nor practice scores select a tree, constant or stopping point. The zero-round candidate permits an honest no-correction result.

The SDK evaluates trees only on the checker's existing, otherwise-supported string-path wrong-word comparisons: complete written and already-accused strings on identical exact frame windows, including any neighbors already selected by the checker. It adds tree vectors to frozen phone logits, renormalizes and compares ordinary complete CTC path sums. A certificate requires finite scores, the shipped scorer preferring the rival, and the corrected scorer strictly preferring the written pronunciation. Ties, unknown phones, impossible complete paths and missing frames abstain. A zero ensemble cannot produce a certificate.

Audio streaming replays each identical primary input and pre-step caches through the diagnostic graph before its evidence reaches the checker. Diagnostic feeds are copied, returned caches never replace primary state, and exact primary/diagnostic phone-output equality is checked on every window. Raw features/logits are retained; trees run only when the checker requests a comparison. Thus the listener can veto at confirmation time. Core retains its original internal confirmation/ownership ledger while reporting the public verdict as uncertain and omitting it from mistakes. Certificates match word identity, both complete strings and exact frame bounds. Graph confirmations remain exempt, and primary phonemes, confidences, posteriors, tracker input and insertion ownership stay unchanged.

Session-end processing retains certificates in serialized evidence and reviews any additional existing comparisons from gap/insertion-enriched evidence, reusing cached observations. Occurrence-specific replay retractions use the original live evidence so a graph confirmation cannot be removed because a stored replay aligns differently. The generic inspection CLI independently replays evidence and asserts unchanged tracker events and added-word decisions.

The Node directory/tier loader requires both declared side files to exist and match their hashes, ties the ensemble to the primary checksum, and validates finite vector leaves, dimensions, feature indices, tree depth and acyclic reachable topology. Missing declared assets fail before inference. The trainer copies the complete primary bundle, including existing side-ear files, and writes the residual descriptor only after writing both side files. `--verify` in the SDK CLI loads the complete bundle and compares primary/diagnostic streaming posteriors and frame clocks on a deterministic waveform.
